## 一、重构目标

当前面板功能已经完整，但前端属于单文件、功能优先的 MVP：深色纯色背景、同尺寸卡片、Emoji 图标、内联事件处理和缺少统一交互层级，使界面容易呈现“自动生成的工具页”观感。

本次视觉重构的目标不是复制参考项目的页面、图标、Logo、字体或源码，而是吸收其成熟的后台产品设计方法：

```text
统一主题变量
+ 可折叠侧边栏
+ 固定顶栏与面包屑
+ 柔和的页面背景层
+ 统一毛玻璃卡片体系
+ 清晰的信息层级
+ 低干扰的微交互
+ 完整的状态、加载、错误和确认反馈
```

重构完成后，面板应呈现为一套稳定、克制、可长期使用的本地运维控制台，而不是带有堆叠装饰的展示页。

## 二、现状审查

### 2.1 当前前端结构

当前界面位于：

```text
static/index.html
```

当前页面将以下内容集中在一个文件中：

```text
CSS 变量
HTML 结构
页面状态
接口请求
SSE 日志
认证逻辑
服务控制逻辑
二维码刷新
凭据复制
```

这让 MVP 交付速度很快，但后续新增备份、配置预览、恢复、认证、操作进度和多页面导航时，维护成本会快速上升。

### 2.2 当前视觉问题

| 现状 | 对体验的影响 | 重构方向 |
|---|---|---|
| Emoji 作为标题、按钮和状态图标 | 图标形态、颜色和基线不一致，工具感较弱。 | 全部替换为统一的 Lucide SVG 图标。 |
| 全页同一深蓝背景 | 页面没有层次，状态和内容区不易聚焦。 | 加入低对比度渐变背景和柔和光斑层。 |
| 所有模块为相近尺寸的普通矩形卡片 | 重要信息与辅助信息权重相同。 | 使用主从卡片、指标区、操作区和工作区分层。 |
| 顶部只是一行标题和操作按钮 | 没有全局导航、当前页面定位和实例状态入口。 | 使用侧边栏、顶部栏、面包屑和实例状态区。 |
| 交互大量依赖内联 `onclick` | 页面复杂后不利于组件复用和状态管理。 | 迁移为 React 组件事件与 hooks。 |
| 缺少全局 Toast、确认弹窗、空状态和骨架屏 | 长任务、失败、停止服务等动作反馈不完整。 | 引入统一反馈组件体系。 |
| 缺少响应式断点和移动端导航策略 | 小屏可能出现内容挤压或横向滚动。 | 加入 375、768、1024、1440 四档布局验收。 |
| 动效仅有加载圆环 | 页面切换、状态变化和任务反馈显得生硬。 | 加入低幅度、短时长、可降级的过渡动画。 |

### 2.3 当前界面中应保留的优点

以下内容不需要推倒重做：

```text
环境检测、服务状态、二维码、凭据、OneBot 配置、使用流程和日志都已具备。
页面信息已经对应现有 FastAPI API。
二维码与日志在同一界面，首次部署流程连续。
深色基础色与日志终端场景天然匹配。
```

重构应保留现有 API 和业务行为，先替换表现层与前端组织方式，再逐步升级交互。

## 三、设计方向：Jade Console

### 3.1 风格定位

采用“Jade Console（玉石深色控制台）”作为本项目独立视觉方向：

```text
深色专业控制台
+ 低饱和石墨黑背景
+ 玉绿色作为唯一主操作色
+ 冰蓝用于信息与网络状态
+ 琥珀用于等待与注意状态
+ 珊瑚红用于停止与错误状态
+ 半透明面板和细边框
```

该方向保留参考项目的柔和背景、玻璃层次、导航结构和微动效方法，但不沿用其粉色猫系主题、专属图形、品牌符号或自定义字体。

### 3.2 色彩 Token

配色规则：

| 场景 | 颜色策略 |
|---|---|
| 主操作 | 玉绿色填充按钮或高亮边框。 |
| 成功/正常 | 玉绿色状态点和低透明度背景。 |
| 信息 | 冰蓝色图标和说明，不抢主操作色。 |
| 等待/需处理 | 琥珀色，搭配明确文字。 |
| 停止/错误 | 珊瑚红色，仅用于破坏性操作和失败状态。 |
| 日志 | 高对比等宽字体，按级别以克制的语义色区分。 |

### 3.3 字体

```text
正文与界面：Inter、Noto Sans SC、Microsoft YaHei、Segoe UI
数字、PID、端口、命令、日志：JetBrains Mono、Cascadia Mono、Consolas
```

规则：

```text
正文最小 14px，移动端正文最小 16px
标题采用 600 至 700 字重，不使用夸张渐变文字
技术数值和日志使用等宽字体
正文行高 1.5 至 1.7
界面标签采用短句和动词开头，避免大段宣传式文案
```

### 3.4 图标规则

采用 `lucide-react`，统一使用 18px 或 20px 描边图标。

建议映射：

| 二维码登录 | `QrCode` |
| OneBot 配置 | `Cable` |
| 日志 | `TerminalSquare` |
| 备份 | `ArchiveRestore` |
| 设置 | `Settings2` |
| 帮助 | `CircleHelp` |
| 启动 | `Play` |

| 成功 | `CircleCheck` |
| 警告 | `TriangleAlert` |

禁止在正式界面中继续使用 Emoji 作为图标、favicon 或状态符号。

## 四、技术架构方案

### 4.1 推荐技术栈

前端独立为 Vite 应用，但仍由 FastAPI 在生产环境提供构建产物：

```text
React 19
+ TypeScript
+ Vite
+ Tailwind CSS 3
+ HeroUI
+ Motion
+ Lucide React
+ TanStack Query
+ React Router
+ react-hot-toast
```

选型原因：

| 技术 | 作用 |
|---|---|
| React + TypeScript | 将当前单文件页面拆分为可复用、可测试组件。 |
| Vite | 提供开发服务器、热更新和构建产物管理。 |
| Tailwind CSS | 统一设计 Token 和组件样式，避免继续堆积内联 CSS。 |
| HeroUI | 提供 Button、Card、Modal、Input、Tabs、Tooltip、Dropdown 等统一基础组件。 |
| Motion | 提供页面切换、侧边栏、弹窗、任务反馈等低成本动效。 |
| Lucide React | 提供一致的线性 SVG 图标。 |
| TanStack Query | 统一管理 `/api` 查询、刷新、错误、轮询和缓存。 |
| React Router | 将概览、服务、日志、备份、设置拆分成真实页面。 |
| react-hot-toast | 全局成功、错误、进行中提示。 |

Redux、复杂表单库、终端模拟器均不作为第一阶段前置依赖。当前数据规模较小，React Query 与局部状态足够。

### 4.3 开发与生产运行方式

开发模式：

```text
Vite：localhost:5173
FastAPI：localhost:8080
Vite 将 /api、/qr.png、/astrbot 代理到 8080
```

生产模式：

```text
npm run build
→ 前端产物输出到 ../static
→ FastAPI 继续通过 / 和 /static 提供前端资源
```

建议 Vite 的 `base` 设为：

```ts
base: '/static/'
```

FastAPI 需保证根路由返回构建后的 `static/index.html`，并继续挂载 `/static` 资源目录。

### 4.4 迁移原则

```text
先新建 frontend，不直接覆盖现有 static/index.html
→ 新前端先只读取现有 API
→ 与现有页面并行验证
→ 新页面覆盖全部功能后再替换生产静态产物
→ 保留旧 index.html 作为回滚文件，直到完成完整验收
```

## 六、页面详细方案

### 6.1 概览页

结构：

```text
页面标题 + “本地实例已连接”状态
├── 服务健康概览（3 张主卡）
├── 当前部署阶段 / 首次部署进度时间线
├── 快捷操作区（安装、全部启动、打开 AstrBot）
├── 最近操作与最近异常
└── 实例信息（路径、端口、配置状态）
```

服务主卡应包括：

```text
服务名称
当前状态：健康 / 等待 / 未启动 / 错误
端口与 PID
最后一次健康检查时间
一键启动、停止、重启
展开查看详情
```

不要把所有服务信息平铺成大表。首屏只显示用户当前最需要判断的内容：是否可用、下一步是什么、哪里有错误。

### 6.2 部署向导页

将当前“使用流程”升级为可执行的纵向步骤向导：

```text
01 环境检查
02 安装依赖
03 配置 OneBot
04 启动服务
05 微信扫码
06 在 AstrBot 配置模型
```

每步包含：

```text
步骤状态
一句解释
主要操作按钮
完成条件
最近操作结果
```

状态不应只依赖颜色，同时使用图标和文字：

```text
未开始、进行中、已完成、需要处理、失败
```

### 6.3 服务中心

采用“服务列表 + 右侧详情抽屉”或“服务卡片 + 展开详情”模式。

建议详情内容：

```text
当前进程 PID
工作目录
启动时间
端口与健康检查
最近 stdout / stderr 摘要
启动、停止、重启操作
```

对停止与重启增加确认弹窗，弹窗中明确显示服务名称、进程 PID 和受影响端口。

### 6.4 连接配置页

页面分为左右两栏：

```text
左栏：二维码和微信登录状态
右栏：AstrBot 凭据、OneBot 配置状态、配置预览、进入 WebUI
```

二维码卡片规则：

```text
登录成功后切换为成功状态，而不是仅把图片降透明度
二维码加载时显示固定尺寸骨架，避免布局跳动
二维码过期时显示“刷新二维码”操作
扫码状态文本始终在二维码下方
```

凭据卡片规则：

```text
密码默认遮挡
显示 / 隐藏和复制为独立图标按钮
来源显示为次要元数据
凭据与 OneBot 配置动作分离，不放在同一个高密度卡片中
```

### 6.5 实时日志页

日志是本项目高频使用场景，应从概览页底部的大块区域升级为独立工作页。

布局：

```text
顶部工具栏：服务 Tabs / 搜索 / 自动滚动 / 清屏 / 复制
主区域：等宽终端视图
右侧可选面板：连接状态、日志文件、最近错误摘要
```

视觉规则：

```text
背景比主页面更深
日志每行保留固定行高
时间、级别、组件名使用低对比次级色
错误和警告只高亮关键词与左侧标记，不整行使用强色
自动滚动关闭时显示“已有 N 条新日志”提示
```

### 6.6 认证页

认证页使用独立纯布局，不显示后台侧边栏。

结构：

```text
页面背景层
→ 中央认证卡片
→ 左上角小型产品标识
→ 密码输入框、错误提示、登录按钮
→ 底部本地实例说明
```

只在 `panel_password` 已配置且会话未认证时展示。认证已关闭时，用户不应感知此页面的存在。

## 八、动效方案

### 8.1 动效原则

```text
动效用于说明状态变化和层级变化，不用于装饰性炫技。
优先使用 opacity 与 transform。
常规微交互为 160 至 220ms。
页面切换不超过 260ms。
长任务使用真实进度或明确等待状态，不使用无限装饰动画代替反馈。
```

### 8.2 动效清单

| 场景 | 动效 | 参数 |
|---|---|---|
| 页面切换 | 淡入 + 向上 12px | 220ms，ease-out |
| 侧边栏展开 | 宽度与内容渐显 | 260ms，spring，低弹性 |
| 卡片首次加载 | opacity + 向上 8px | 180ms，按区块错开 30ms |
| 按钮提交 | 图标替换为 spinner，宽度固定 | 160ms |
| 状态切换 | 状态点颜色和文字交叉淡入 | 180ms |
| Modal | 背景遮罩淡入，内容 scale 0.98→1 | 180ms |
| 二维码刷新 | 图片淡出、骨架显示、淡入 | 200ms |
| 日志新增 | 无逐行进入动画，直接插入避免干扰 | 无 |

### 8.3 限制

```text
概览卡片不使用持续 3D 旋转。
背景光斑不持续漂移，避免影响日志和状态读取。
不使用大面积霓虹、扫描线、粒子、矩阵雨或夸张渐变字。
尊重 prefers-reduced-motion：关闭非必要入场和过渡动画。
```

## 九、数据交互与状态管理

### 9.1 API 客户端

统一由 `api/client.ts` 处理：

```text
JSON 解析
401 自动跳转认证页或刷新认证状态
统一错误对象
请求取消
请求超时
Toast 错误提示
```

### 9.2 查询策略

| 数据 | 方式 | 刷新频率 |
|---|---|---|
| 环境状态 | React Query | 首次、手动刷新、安装完成后 |
| 服务状态 | React Query | 5 秒；页面不可见时暂停或降频 |
| 二维码状态 | React Query | 未登录时 3 秒，登录后停止轮询 |
| 日志 | EventSource | 当前日志页激活时连接，离开时关闭 |
| 凭据 | React Query | 初次加载和配置后失效重取 |
| 备份列表 | React Query | 页面进入时和恢复、备份后失效重取 |

### 9.3 写操作交互

所有会改变运行状态的操作采用同一流程：

```text
点击操作
→ 必要时确认弹窗
→ 按钮进入 loading 且禁止重复提交
→ Toast 显示任务已开始
→ 刷新相关查询
→ 成功显示结果与下一步建议
→ 失败显示服务名、步骤和“查看日志”入口
```

停止、恢复和覆盖配置属于破坏性操作，必须显示确认弹窗。

## 十三、最终决策

本项目的前端重构采用以下方案：

```text
视觉：参考成熟后台产品的导航、玻璃层次和克制动效，使用本项目自己的 Jade Console 主题。
技术：React + TypeScript + Vite + Tailwind + HeroUI + Motion + Lucide + React Query。
迁移：新建 frontend 工程并通过 API 代理并行开发，完整验收后构建替换 static 目录。
范围：优先概览、部署向导、服务中心、连接配置、日志与认证页面。
原则：保留现有 FastAPI 业务接口，先改善体验与可维护性，再扩展高级功能。
```
